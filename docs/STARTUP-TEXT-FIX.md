# 0.4.12 · 默认场景启动与中文录制修复

## 默认场景没有执行

本次只读检查确认：应用收到了 `--startup`，但默认场景包含 GUI 点击，策略仍为 `blockAtStartup`，整个场景在创建运行记录前被拦截。旧版只留下短暂的触发事件，用户看不到明确原因。

新版设置页会检查默认场景、登录触发器、策略、参数和应用配置。启动被阻止时会通知并保留失败运行、启动结果和原因；节点标记为未执行。设置中的 **允许默认场景自动执行** 会保存当前默认场景的允许策略，不立即运行。版本检查防止授权时场景已被替换。已有子场景仍遵循各自策略，必要时在其编辑器中调整。

此外，修复已运行的 LaunchFlow 收到首次 `--startup` 时忽略默认场景的问题；重复指令在同一实例中只分发一次。Windows 普通登录启动的可执行文件和测试参数正确引用，并检测路径失效；可点击 **修复普通登录启动** 重新登记。禁用的登录触发器仍保持禁用，并显示原因。

升级后到 **设置 → 启动与后台**，确认默认场景自动执行检查通过。你的现有默认场景需要点击一次 **允许默认场景自动执行**。不会在升级时静默修改已有场景的安全策略。

## 开机直接进入桌面

Windows 支持系统自动登录；普通桌面工作流不能在 Winlogon 安全桌面输入密码解锁。根据用户选择，本版增加 **Microsoft Autologon 配置入口**，打开微软官方工具页面；密码在微软工具中填写，由 Windows 管理，LaunchFlow 不读取或保存密码。

1. 点击入口，下载并运行 Microsoft Autologon，在工具中配置 Windows 账户与密码，点击 Enable。
2. LaunchFlow 选择 **普通登录启动**，确保默认场景自动执行检查通过。
3. 下次开机由 Windows 登录，再执行默认场景。普通锁屏不会自动解锁；在微软工具中点击 Disable 可撤销系统自动登录。

设置页只读取 `AutoAdminLogon` 启用标记，不读取 `DefaultPassword` 或 LSA 秘密。标记不等于账户或组织策略验收成功。配置后设备直接进入账户桌面，能接触设备的人也能使用它；系统管理员可能读取自动登录凭据。

参考：[Microsoft Autologon](https://learn.microsoft.com/en-us/sysinternals/downloads/autologon)、[Windows Credential Providers](https://learn.microsoft.com/en-us/windows/win32/secauthn/credential-providers-in-windows)。原有“解锁前准备桌面应用”仍使用 Windows ARSO，保留锁屏；与直接进入桌面是不同配置。

## 微信中文输入

只读能力检查确认本机微信输入框提供 ValuePattern 和 TextPattern。旧录制器只监听 ValuePropertyChanged；中文输入法的提交可能仅通过文字变化通知或可读取内容体现，导致漏录。

- 同时监听 TextPattern 文字变化，并检查录制目标中当前输入框的文字，捕获中文提交后的结果，不把拼音按键拼成文本。
- 连续编辑合并为完整文本动作，不再因输入停顿或动态控件名称分裂成多个无效定位。输入框及父级的动态名称不用于录制定位，保留角色、类名、AutomationId 与层级。
- 回放先激活并聚焦真实输入框。ValuePattern 未实际更新时，使用系统 Unicode 输入；随后检查文字是否生效。无法确认时报告 `textNotApplied`，不继续假报成功。
- 暂停期间的内容不写入录制；密码字段仍只生成 Secret 引用。不支持文字读取的输入框会给出明确提示；审阅页可直接修改录制文字。
- 文字读取放在录制器消息循环，避免在低级键盘钩子内同步调用目标 UIA 而阻塞输入。

旧记录若缺少文本动作，需重新录制，或添加 Input Text 并重新拾取输入框。录制中文时先完成候选词选择，再停止录制。

## 验证范围

使用独立 SQLite、专用计划任务和测试窗口，验证普通登录入口、已有实例启动、计划任务启动、策略拦截与授权、重复指令去重。文字测试使用独立 WPF 输入框模拟 ValuePattern 假成功与 TextPattern 返回中文，验证真实 Unicode 投递、录制、编辑、暂停和回放。

不会操作微信聊天、发送消息、读取 Windows 密码或更改自动登录策略。本轮不进行真实重启、ARSO 或 Windows 自动登录验收；真实微信输入法候选提交仍由用户升级后验收。
