# 0.4.11 · 微信录制点击位置修复

0.4.10 的用户日志显示：激活窗口及三个点击节点均成功。只读检查对应运行快照后确认，三个点击的 Accessibility Locator 都是 `Window`，匹配矩形与整个微信窗口相同，未保存真实点击坐标。因此旧回放实际上连续点击窗口中心，无法重现用户点击的区域。

## 修复行为

- 物理鼠标点击在按下时捕获真实位置与窗口边界，生成窗口相对坐标。不会等点击改变界面后再把命中的整个窗口误当成按钮。
- 快速连续点击不再套用 1.5 秒去重规则；文本输入仍可合并。物理点击伴随的 UIA Invoked 事件被抑制，避免重复插入动作；独立的语义调用仍可录制。
- Pick Element 遇到整窗或不提供按钮语义的容器时，保存实际拾取位置；可访问按钮继续保留语义定位。
- 回放前验证准确的目标前台窗口及点击位置的实际命中窗口。被其他窗口遮挡时返回 `targetObscured`，不点击遮挡窗口。
- 鼠标先移动到目标并给予界面处理悬停的时间，再发送按下/抬起。
- 旧的整窗点击返回 `impreciseClickTarget`，编辑器提示重新录制或拾取；不会继续点击窗口中心后显示成功。
- 诊断日志增加节点类型、点击执行方式、定位来源、控件类型、命中结果与已发送按钮事件数；仍不导出实际坐标、窗口标题、聊天或输入文字。

## 旧录制处理

**0.4.10 及以前录下的这类整窗点击没有保存原始位置，无法自动还原。** 升级后重新录制这些点击，或进入对应点击步骤使用 Pick Element 重新拾取；激活窗口步骤可保留。无需删除整个场景或修改应用授权。

相对坐标支持窗口平移；目标应用布局、缩放或控件排列改变后应重新拾取。鼠标事件成功投递不等于目标应用业务流程已经完成，必要时在点击后添加等待目标元素等状态检查。

## 验证

独立 WinForms 自绘窗口不提供内部按钮的 UIA 语义，模拟本次微信的关键条件。专项脚本 `node scripts/recorded-click-smoke.mjs` 验证真实鼠标录制、三个偏离中心的位置、移动窗口后回放、整窗旧记录拦截、窗口遮挡保护、拾取不触发点击，以及通过真实 Tauri/Rust 工作流保存并回放。

测试只使用隔离的数据目录和自己的窗口，不操作微信聊天或发送消息。本版证据位于 `artifacts/recorded-click/evidence/`。
