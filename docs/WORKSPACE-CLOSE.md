# 关闭工作区应用（0.4.9）

## 使用

1. 打开 **工作区 → 关闭工作区应用**。面板打开时自动捕获应用，无需先保存工作区或场景。
2. 勾选需要退出的应用。首次发现的普通应用默认勾选，系统组件、LaunchFlow 和无法核实身份的应用不可选择。支持全选 / 全不选；同一路径的多个实例合并为一行。
3. 点击 **一键关闭所选应用**。Windows 向捕获的主窗口发送正常关闭请求，然后等待约 4 秒并检查进程是否退出。保存提示需要用户在原应用处理；关闭窗口后仍驻留托盘的应用显示“仍在运行”。
4. 可以点击 **检查退出状态** 继续等待；正常关闭后仍在运行的已选应用才出现 **强制关闭剩余 N 个**。再次列出应用并确认后才强制退出，未保存的数据可能丢失。不会因超时自动强制退出。
5. **设置 → 关闭工作区快捷键**，输入例如 `Ctrl+Alt+Q` 并点击 **保存快捷键**。留空保存可禁用。快捷键唤起同一确认面板，不直接关闭应用；面板已打开时保持当前勾选。关闭窗口驻留托盘时也可以唤起。

## 捕获与记忆

- Windows 捕获当前桌面的可见窗口，包括最小化窗口；跳过 DWM cloaked（例如其他虚拟桌面）窗口。纯后台服务、没有可见窗口的托盘应用不在捕获列表中。
- 同一路径的应用实例合并；勾选和取消勾选立即存入 SQLite。应用退出、重新启动、重新捕获、LaunchFlow 重启都保留。暂时消失的应用不会删除偏好；路径变化视为新应用。
- 捕获只包含当时的实例。之后新启动的同名应用不会被旧列表关闭。捕获 15 分钟后过期，需重新捕获。
- 系统组件和 LaunchFlow 被保护。管理员应用拒绝普通权限关闭时，会请求一次 Windows UAC；用户确认后由临时助手重试本批被拒绝的原窗口，仍采用正常关闭。取消授权不会自动重试或提供未经正常关闭的强制结束。
- 强制退出前再次核对进程路径、PID、创建时间，并持有实际进程句柄。只终止已尝试正常关闭的剩余实例，不结束进程树。若应用有新窗口或其他桌面的窗口，拒绝强制关闭并提示重新捕获。
- SQLite 数据库迁移到版本 3，原场景、历史、应用库和设置保留；旧版本无法打开迁移后的数据库。

## 快捷键

要求至少包含 Ctrl、Alt 或 Command / Super 等修饰键。检测与场景快捷键、其他应用占用的冲突；注册失败保留上次有效设置。重启重新注册，失败可在设置页查看并修改。保存场景、刷新场景快捷键不会清除关闭工作区的快捷键。

## 0.4.9 管理员应用关闭

权限差异会触发 Windows UIPI 限制，`PostMessage` 被阻止时返回错误码 5；这就是旧版“管理员应用请手动退出”的来源。[Microsoft PostMessage 文档](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-postmessagew)

点击“一键关闭所选应用”即可；出现 Windows 授权窗口时亲自确认。需要当前账户具备管理员资格，不要求整个 LaunchFlow 长期以管理员权限运行。不借用应用启动的预授权任务，不保存关闭授权。一次关闭批次只为权限被拒绝的目标请求一次授权；检查退出状态不请求 UAC。

正常关闭已发送但应用仍运行时，可以继续等待或单独确认强制关闭。管理员进程的强制关闭可能再次请求 UAC；拒绝、超时或通信失败会显示错误，需检查退出状态。保存对话框不会被自动点击。

管理员助手通过仅当前用户可连接的随机命名管道接收目标，双向核验调用进程 ID，检查父进程创建时间、会话和助手路径。授权返回后再次核对目标路径/PID/创建时间/原窗口，不按进程名批量结束，不终止新窗口或进程树。调用方消失或请求过期后不会继续处理剩余目标。

2026-10-08：10 项已有工作区关闭桌面回归通过；新增 6 项原生授权路由检查验证只重试权限拒绝的目标、保留正常结果、取消不强制、状态查询不授权、非法助手请求拒绝。默认 `npm run test:workspace-close-admin` 不弹 UAC，使用授权结果桩；真实高权限进程退出尚待用户确认 UAC 验收。可运行 `node scripts/test-workspace-close-elevation.mjs --approve`，它只创建和关闭独立测试窗口，包含正常退出与明确选择的强制 fallback，需亲自确认数次系统授权。
