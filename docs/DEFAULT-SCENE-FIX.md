# 默认启动场景与五角星状态修复（0.4.7）

## 问题与修复

“我的场景”的五角星按钮原本已在保存后调用刷新，但全局刷新会直接复用进行中的请求。如果后台同步请求在保存前已取得旧数据，保存后的刷新仍等待同一个旧请求，导致数据库已切换默认场景，界面却显示原来的默认标记。

0.4.6 加入了串行合并刷新，但默认标记仍依赖整页读取。列表还会把新默认场景移动到第一位，导致原来点击的位置换成另一张卡片的空心星。0.4.7 改为：

- 点击后立即更新共享的默认状态，所选星星变为绿色实心并带浅绿色背景；保存失败撤回该临时状态。
- 保存命令直接返回已保存的场景 ID，前端据此确认状态，不再等待加载运行历史等整页数据。保存期间开始的旧后台读取由修订号识别并重新读取，不能覆盖新选择。
- 场景列表按更新时间和固定 ID 排序，不再因为默认标记变化而移动卡片。默认标签中的星星也改为实心。
- 后端只更新默认设置与触发器缓存，不为这一操作重建内容未变化的托盘菜单或重新注册快捷键。
- 默认状态在“我的场景”、概览和设置中共享，选中按钮有 `aria-pressed` 语义。

## 验收

`node scripts/default-scene-smoke.mjs` 使用独立测试数据库和真实 Tauri / WebView2 界面，控制旧的后台读取响应返回时机，复现了修复前“数据已保存、旧标记不更新”的问题。

0.4.7 的 7 项桌面检查全部通过：点击后位置不变及图标填充；延迟保存响应时立即显示实心并在成功后保持；旧后台读取与默认切换并发；首页及设置页同步；并发取消默认；失败回退；重启持久化。

验收读取了实际 SVG 路径的填充样式，并截取星星图像检查中心像素。选中星星的中心像素为 `(8, 127, 109)`，与主题实心色一致。修复前点击卡片的 X 坐标从 `733.5` 变为 `264`；修复后保持 `733.5`。

前端 9 项测试、Clippy 和生产构建通过；已有桌面集成流程 8 项通过，覆盖场景创建/编辑、运行事件、草稿恢复、默认场景唯一性、历史删除、取消运行、托盘后台及默认场景登录启动。专项记录、修复前后的截图与安装包校验记录保存在 `artifacts/star-state-fix/evidence`。
