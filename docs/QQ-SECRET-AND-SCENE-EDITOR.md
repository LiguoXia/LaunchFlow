# QQ Secret 输入与场景编辑 · 0.4.14

## QQ 密码录制回放

用户的 0.4.13 诊断中，激活窗口、点击和普通文本输入成功，`gui.inputSecret` 在 Accessibility 查找时返回 `notFound`。读取对应失败快照后，定位器指向 QQ 的临时 Win32 `Edit` 密码控件。

实机校验发现，该控件具有键盘焦点，`IsPassword=true`，但 `IsOffscreen=true`，并且可能只由 `FocusedElement` 提供；常规 ControlView / RawView 中只有 Chrome 的普通输入框。系统还可能将临时控件的句柄作为前台句柄，它的根窗口才是 QQ 登录窗口。旧代码按可见性过滤，并要求前台句柄与根窗口完全一致，因此无法定位和输入。

现在 Secret 查找会在目标窗口的 ControlView、RawView 和聚焦控件中查找唯一密码框。报告 offscreen 的控件只有在目标根窗口处于前台、且该密码框确有键盘焦点时才可使用。普通输入框、其他窗口的控件、多重匹配和未聚焦的 offscreen 密码控件仍被拒绝。点击后密码控件延迟出现时，查找有短暂、有界的重试。

新录制保存 `secure=true`；对于没有稳定 ID 的 Chromium 临时 Win32 密码代理，省略易变的 class / framework。旧式 QQ 密码代理定位在 Secret 查找中自动兼容，保留窗口、祖先、稳定 ID 与运行时控件校验。QQ 这类代理通过已验证焦点后的键盘输入回放，避免 `SetValue` 只更新隐藏编辑框。Secret 值仍从引用读取，录制不读取密码；失败截图的密码遮罩同时考虑 RawView 和聚焦控件。

升级后可复用旧场景中的 QQ Secret 步骤。运行历史的“继续执行”仍复用已成功节点；如果 QQ 登录页面或点击布局已改变，需要重新拾取对应点击位置。

## 场景改名

- 「我的场景」卡片新增「重命名场景」按钮，确认后立即保存。名称去除首尾空格，并校验空名称、长度和并发版本冲突。
- 改名保留场景 ID、默认场景状态和工作流，生成新版本；历史运行快照保持原名称。
- 未完成草稿的工作流保留，名称和基础版本同步。原本已经过期的草稿继续保持过期，避免掩盖版本冲突。
- 编辑器标题旁也可改名，修改进入草稿，可撤销 / 重做，点击「保存」后正式生效。

## 简单编排拖拽

Windows 的 Tauri WebView 默认接管 HTML5 拖放，本版关闭该接管。拖动卡片头部，可插入另一张卡片前 / 后或流程末尾；绿色插入线提示落点。放下后同时更新顺序、依赖连线与位置，支持撤销 / 重做、草稿自动保存和重启恢复。原有上移 / 下移按钮保留。分支工作流继续在高级画布编辑。

## 验证

- `npm test`：顺序、插入位置、无效 / 空操作与既有前端用例。
- `npm run test:core`：核心用例，包括改名的草稿、默认状态、历史快照、名称校验与冲突保护。
- `npm run test:recorded-secret`：隔离密码窗口验证旧 QQ 代理属性、延迟 RawView、录制脱敏、歧义、普通输入框拒绝、已聚焦 / 未聚焦 offscreen 密码框。
- `npm run test:scene-editor`：真实 Windows WebView2 / Tauri IPC / SQLite 验证改名、真实鼠标拖拽、撤销 / 重做、导航恢复、重启持久化和完整 Rust 工作流的 Secret 回放。
- `npm run test:window-focus`：前台子控件与目标根窗口关系、焦点丢失保护和既有激活行为。
- 中文文本与既有原生操作回归。

实机 QQ 只校验了旧录制的点击和密码控件定位，定位通过；密码输入使用隔离窗口和虚构 Secret 验证，未执行实际 QQ 登录。证据在 `test-results/recorded-secret/` 和 `test-results/scene-editor/`。本次验收环境为 Windows，macOS 尚未进行实机验证。
