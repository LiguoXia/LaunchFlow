# 启动与 GUI 诊断日志 · 0.4.13

内置自动登录窗口的密码不进入应用日志、命令行或导出。启动诊断只包含启用状态、是否由 LaunchFlow 登记及操作结果消息，不包含账户密码或 LSA 内容。

出现启动问题后，在「运行历史 → 失败记录」或「设置 → 诊断与更新」点击「复制诊断日志」。日志会复制到剪贴板，同时打开文本预览，可直接粘贴到问题反馈。若剪贴板不可用，预览中会提示手动全选并复制。不会自动上传日志。

日志覆盖 Windows 管理员启动及预授权状态查询、登记、撤销、启动。记录请求编号、时间、阶段、耗时、结果、Windows HRESULT/错误码、异常类型和不带源文件路径的调用方法；原生响应包含 Windows 和 .NET 版本。取消或超时中断也留下记录。从运行详情复制时还包含该运行的状态、节点耗时、重试次数和错误分类。

0.4.10 起，在「运行历史 → 对应运行」复制诊断日志或导出包含该运行的诊断 ZIP，还会包含 GUI 错误码、定位尝试的类型/结果/耗时，以及窗口激活阶段、等待耗时、前台匹配、激活请求和权限交接结果。无需录制或复制聊天内容。这些信息来自已保存的运行历史；设置页未选择具体运行时，复制的启动步骤日志不包含这些 GUI 节点详情。

0.4.11 增加节点类型和点击诊断：执行方式（系统鼠标输入或 UIA 语义调用）、定位来源、控件类型、位置命中是否属于目标窗口、已发送的按钮事件数及执行阶段。整窗旧点击会报告 `impreciseClickTarget`，遮挡会报告 `targetObscured`。导出不包含实际坐标、控件名称或聊天内容；发送输入成功也不代表业务操作完成。

0.4.12 中，文字输入定位过宽会报告 `impreciseTextTarget`，回读无法确认文字生效会报告 `textNotApplied`。默认场景在启动检查阶段被拒绝也会保存失败运行；设置页的“复制启动诊断”会包含检查结果及上次分发是否被阻止，不包含 Windows 登录密码。

不记录程序路径、名称、启动参数内容、环境变量、凭据、输入内容、截图、命令输出和原始异常文本。应用路径与配置标识仅存 SHA-256 摘要，用于关联相同应用的请求。磁盘日志和导出内容采用字段白名单。

Windows 标准安装的数据目录下为 `automation\logs\application.jsonl` 和 `application.previous.jsonl`，通常位于 `%APPDATA%\app.launchflow.desktop\automation\logs`。每个文件上限约 1 MiB，写满后轮换，最多约 2 MiB；重启后保留。复制和 ZIP 导出包含最近 120 条有效记录，损坏或未写完的记录会跳过。诊断 ZIP 新增 `application-log.json`。普通权限的直接启动、GUI 操作和命令执行仍使用已有运行历史/诊断信息，不属于这份管理员启动步骤日志。

日志写入失败不会改变应用启动结果。日志不是审计记录：当前用户可以读取、修改或删除本机日志；它用于故障排查。

0.4.4 已验证失败诊断经真实 Rust/原生桥接持久化、取消记录、大小轮换、损坏尾记录处理、内容过滤、ZIP 导出、重启保留、真实系统剪贴板内容比对，以及复制失败时的手动方式。0.4.10 新增 GUI 焦点错误通过真实 Tauri/原生链路进入复制日志的验证，以及 GUI 内容在复制/ZIP 导出中的白名单过滤测试。
