## macOS 使用

在「关于本机」查看芯片类型，下载对应 DMG，将 LaunchFlow 拖入「应用程序」，再启动。自动化功能按需在「系统设置 → 隐私与安全性」允许 LaunchFlow 的「辅助功能」「屏幕录制」「输入监控」，授权后完全退出并重新打开。AX 用于控件定位和窗口操作，ScreenCaptureKit / Vision 用于截图和 OCR，凭据保存在本机 Keychain。

这是预发布版本：Windows 没有发行证书签名，Mac 使用 ad-hoc 签名，没有 Apple Developer ID 签名或公证。首次打开可能被系统阻止；仅在核对来源和校验值后，在「隐私与安全性」中允许打开。如系统仍提示应用损坏，可针对已核对的应用执行 `xattr -dr com.apple.quarantine /Applications/LaunchFlow.app` 后重试。自动更新未配置，请手动安装新版本。

## 更新内容

- 修复 Mac 原生工作区关闭逻辑中的 Swift 类型错误，恢复两个架构的可编译性。
- Intel 和 Apple Silicon 使用对应架构的 GitHub Mac 构建机；主程序和原生自动化 / 练习程序一起打包并检查架构与签名。
- 新增发布流水线：测试、构建、包内原生程序检查、Mac 主程序启动检查、SHA-256 验证全部成功后才公开 GitHub Release。
- 包含 [v0.4.20](https://github.com/LiguoXia/LaunchFlow/blob/v0.4.23/docs/releases/v0.4.20.md) 的 Chromium 文本录制跨重启定位修复、[v0.4.21](https://github.com/LiguoXia/LaunchFlow/blob/v0.4.23/docs/releases/v0.4.21.md) 的指定时间一次性触发器、[v0.4.22](https://github.com/LiguoXia/LaunchFlow/blob/v0.4.23/docs/releases/v0.4.22.md) 的 Windows 托盘隐藏主窗口恢复。

Windows 自动登录、UAC 预授权及 Windows 体验模板仍是 Windows 功能。跨平台导入场景时需要绑定 Mac 应用路径 / Bundle ID，并重新定位不同平台的 GUI 控件。Mac CI 编译与启动检查不等于用户实际桌面的录制回放、多屏和系统授权验收；这些功能仍需在目标 Mac 上验证。
