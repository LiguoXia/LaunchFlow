# LaunchFlow v0.4.24

本地测试版本：改善 Windows 托盘应用恢复，微信点击问题已验证。后续实测发现 ChatGPT / Codex 真正隐藏到托盘后仍可能无法点击，此问题由 **v0.4.25** 修复。

- 旧实现只调用 Win32 `ShowWindowAsync`，将隐藏 HWND 强行显示；Qt / Chromium 应用的内部隐藏状态可能仍未恢复。
- Qt 窗口通过 UI Automation 的窗口恢复接口恢复，其他窗口通过应用线程处理的标准窗口恢复命令恢复。已被旧版显示成不可交互的 Qt / Chromium 窗口，再执行「激活窗口」也会修复，无需退出应用。
- 恢复隐藏最大化窗口时保留最大化状态。只在目标窗口可见、启用、输入线程响应且获得前台焦点后报告成功；被对话框禁用或没有响应的窗口不会接收输入。
- 排除微信等应用的托盘消息窗口及过小的隐藏辅助窗口，避免把通知用 HWND 当成可交互主窗口。
- 诊断日志增加恢复方式、窗口启用状态、线程响应状态；仍不导出窗口名称、句柄、用户输入或截图。

现有场景不需要重新录制。升级后重新执行「激活窗口」，然后执行原有点击步骤。

验证：旧版在独立 WinForms 托盘测试应用中复现「激活成功、点击事件已发送、按钮没有响应」；修复后通过实际鼠标点击和完整保存工作流的「托盘恢复 → 点击按钮」检查。另覆盖最大化保留、普通最小化、重复匹配、失效句柄、应用重启及不可交互窗口保护。用户确认微信点击恢复；此前 Codex 检查仅覆盖已显示窗口，未验证真实隐藏到托盘的完整恢复过程。

本次修复针对 Windows，macOS 原生恢复逻辑没有改动。Windows 构建仍未使用发行证书签名，自动更新未配置，请手动升级。
