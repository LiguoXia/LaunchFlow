# LaunchFlow v0.4.25

新增工作流「复制文本」步骤，并修复 Windows 上 ChatGPT / Codex 从系统托盘激活后无法点击的问题。现有场景无需重新录制。

在工作流编辑器的「系统」步骤列表添加「复制文本」，只需填写要复制的内容。运行时文本写入系统剪贴板，保留中文、换行和空格；然后添加原有「组合快捷键」步骤，Windows 用 `Ctrl` + `V`，macOS 用 `Command` + `V`，即可粘贴到目标应用。复制步骤无需配置窗口或元素，剪贴板占用时会提示失败，不会误报成功。Windows 和两个 macOS 架构均支持。

内置 Windows 体验模板增加复制文本示例，共 33 种步骤、43 个主场景步骤。

剪贴板验证覆盖中文、多行和空格在原生工作进程结束后仍然保留、被其他应用占用时正确报错，以及编辑器添加 / 保存配置后完整工作流的实际 `Ctrl+V` 粘贴。运行输出仅记录复制成功与字符数，不重复记录文本。

- Chromium / Electron 的标准 Win32 恢复命令只显示外层窗口，内部页面仍可能隐藏。对于拥有 Windows 注册应用标识的 Chromium 窗口，现在使用应用自己的 AppsFolder 激活入口，由它恢复窗口和页面。
- 已被旧版显示成不可交互的窗口也可修复：先清除外层残留窗口，再等待应用自行显示同一个目标窗口，避免把旧的可见状态当成恢复成功。每次激活只发送一次应用恢复请求。
- 保留 v0.4.24 的微信 / Qt 恢复、最大化状态保留及托盘辅助窗口排除。被对话框禁用、失去焦点或没有响应的窗口不会接收输入。
- 应用恢复允许最多五秒；失败会停止后续输入。不会重新执行未注册应用的任意可执行文件或旧启动参数。
- 诊断仅记录恢复方式和窗口响应状态；不导出应用注册标识、窗口名称、用户输入或截图。

验证：独立 Electron 33.4.11 测试应用复现旧路径的「窗口可见、前台确认、点击已发送，但页面仍隐藏、点击数为 0」。新路径通过真实鼠标输入验证页面可见、按钮收到点击；覆盖已经显示的残留窗口、再次隐藏到托盘、重复恢复和最大化保留。原生激活回归测试 27 项通过。用户已在实际 ChatGPT / Codex 客户端从托盘恢复后确认手动点击和后续自动点击均正常。

可选 Electron 回归检查：设置 `LAUNCHFLOW_ELECTRON_TEST_RUNTIME` 为本机独立 Electron 运行时路径，然后执行 `npm run native:build` 和 `npm run test:electron-tray`。测试只操作自身的独立窗口。

提供 Windows x64 安装包 / 便携 ZIP，以及 macOS Intel、Apple Silicon 的 DMG / ZIP。macOS 原生恢复逻辑没有改动，最低系统版本仍为 macOS 13。

此版本仍为预发布：Windows 无发行证书签名；macOS 使用 ad-hoc 签名，未公证。自动更新未配置，请手动升级。Windows 运行需要 WebView2 与系统 .NET Framework。
