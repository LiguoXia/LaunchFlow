# LaunchFlow v0.4.20

修复在 Codex / ChatGPT 等 Chromium 桌面应用中录制文本后，退出并重新打开应用时出现 `notFound: No accessible element matched the locator` 的问题。

- 原因：输入框定位保存了 React 每次渲染可能变化的 `useId`（例如 `_r_g9_`），以及 ProseMirror 编辑器临时的焦点 / 选区 CSS 类。控件层级没有变化时，这些临时值也会导致严格匹配失败。
- 新录制在保存控件及其祖先属性时排除这些临时值；旧场景在执行匹配时使用相同规则，无需重新录制或修改已有场景。
- 保留窗口范围、控件类型、框架、显式稳定 ID、祖先层级和编辑器主体类名。多个输入框仍返回歧义错误；密码输入和发送前焦点检查不变。此修复不保证跨应用页面结构变更的录制自动适配。

回归测试 `npm run test:recorded-restart` 使用独立 Microsoft Edge 窗口和真实 Windows UIA：录制中文、保存 JSON、退出浏览器、以不同 React ID 重启，在未聚焦编辑器中执行旧场景，再次重启执行新录制；另验证稳定祖先 ID 不匹配、多个编辑器时不会输入。修改前复现相同 notFound，修改后通过。测试没有操作用户的 Codex 对话或发送消息。

验证通过：6 项重启回放检查、5 项中文录制 / 输入检查、5 项密码录制 / 输入检查、11 项原生定位与凭据约束检查，以及 17 项前端测试。

本地 Windows x64 安装包与便携包位于 `artifacts/recorded-restart/windows/`。构建未签名，未配置自动更新；本轮未发布 GitHub。
